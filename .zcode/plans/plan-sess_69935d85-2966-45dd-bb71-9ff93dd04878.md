Add real-time push via Server-Sent Events: the Flask server emits a change event whenever it writes data, and the UI subscribes and reloads the affected tab.

## Backend (server.py)
**SSE plumbing:**
- Add `queue`, `threading` imports; add `Response` to the existing `flask` import.
- A module-level `_sse_clients` list of `queue.Queue` + `_sse_lock`. `emit_event(event)` pushes a dict to every client queue under the lock.
- `_emit_for_path(path)`: derive the event kind from the filename — `phrases.json`→phrases, `futures.json`→futures, `prompts_<platform>.json`→prompts — with `project_id = path.parent.name`. No-op for unrecognized paths.
- New `GET /events` route: registers a `queue.Queue`, returns a `Response(mimetype="text/event-stream")` generator that yields `": connected\n\n"`, then blocks on `q.get(timeout=15)`, yielding `data: <json>\n\n` per event or a `": keepalive\n\n"` comment every 15s. Unregisters in a `finally`. Headers disable buffering/proxy caching.
- Set `threaded=True` on `app.run(...)` so the long-lived SSE stream doesn't block other requests.

**Instrumentation:**
- Call `_emit_for_path(path)` at the end of `write_prompts()` — covers all 8 write sites automatically (prompt POST, phrase POST/DELETE, future POST/DELETE/order, rename restamp).
- Emit `{"type": "projects"}` explicitly in `create_project`, `rename_project`, `delete_project` (they bypass write_prompts via shutil).

## Frontend — new `src/events.ts`
- A singleton `EventSource('/api/events')` (opened lazily on first subscriber; auto-reconnects natively on drop).
- `subscribe(handler) → unsubscribe`. Parses each SSE `data` message as JSON and fans out to handlers. Typed union: `phrases|futures|prompts` (with `project_id`) or `projects`.
- Vite's proxy streams SSE without buffering; no vite.config change needed.

## Frontend — each tab subscribes (small additions)
A `useEffect` per tab that calls `subscribe` and re-`load()`s when the event matches its current project / kind:
- **PhrasesTab**: `{type:'phrases', project_id}` matching `currentProject`
- **FutureTab**: `{type:'futures', project_id}` matching `currentProject`
- **PromptsTab**: `{type:'prompts', project_id}` matching `currentProject` (fetches all platforms, so any platform change reloads it)
- **ProjectsTab**: `{type:'projects'}` → reload the project list

## Notes
- The acting client gets its own event echo → one extra harmless reload (it already reloads after each mutation today). The real value is **other clients, other tabs, and out-of-band backend/file changes** now refresh live.
- EventSource retries on backend downtime; no infinite-spin cost.
