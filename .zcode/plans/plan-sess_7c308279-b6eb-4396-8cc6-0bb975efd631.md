## Skills tab (global)

Add a global **Skills** tab to the left pane. A multi-line textbox (starts 3 lines, grows to 11) at the top adds a skill item on **Enter**; items render below with the duplicate / copy / edit / delete icon set (mirroring `PhrasesTab`). Because it's **global**, it's stored at the server root (not under a project) and is always enabled regardless of the selected project.

### Backend — `/home/ace/ai/abar/server.py`

Storage location: `project_data/skills.json` (root level, not under a project dir). Shape: `[{skill_id, text, project_id}, ...]` to stay consistent with the existing entry dicts (project_id will be `None`/absent for global).

1. Add `skills_file_path()` → `PROJECT_DATA_DIR / "skills.json"` (root; no per-project subpath, no project_id param). Keeps the same temp-write + resolve-safety pattern.
2. **GET `/skills`** → return the array `[{skill_id, text}]` (drop `project_id` from output like `get_futures` does).
3. **POST `/skill`** → upsert by `skill_id` (server generates `uuid4().hex` when absent); body `{"text": ...}` (+ optional `skill_id`). `text` must be a non-empty string. Reuses the same find-and-replace-or-append logic.
4. **DELETE `/skill?skill_id=Y`** → idempotent delete, 200 whether or not it existed.
5. Update `_emit_for_path` to recognize `skills.json` at the root → `emit_event({"type": "skills"})` (no `project_id`).
6. Update the module docstring to mention the skills endpoints/file.

### Frontend

7. **`src/types.ts`** — add `export interface Skill { skill_id: string; text: string }`.
8. **`src/api.ts`** — add `fetchSkills()`, `upsertSkill(text, skillId?)`, `deleteSkill(skillId)` (no project_id params; plain `/api/skills`, `/api/skill`, `/api/skill?skill_id=`).
9. **`src/events.ts`** — extend `ServerEvent` union with `| { type: 'skills' }`.
10. **`src/components/tabs/SkillsTab.tsx`** (new) — global component (no `useCurrentProject`). Structure mirrors `PhrasesTab` but:
    - The input is a **textarea** (3→11 line autosize via the same `autosize` ref pattern from `FutureTab`) instead of a single-line filter.
    - **Plain Enter** adds the item (trims; ignores empty); **Ctrl/Cmd+Enter** inserts a newline (reuses `document.execCommand('insertText', false, '\n')`); **Escape** clears.
    - On add: `upsertSkill` → reload → also `copyText(value)` to clipboard (matches Phrases/Future).
    - Row actions: **duplicate, edit, copy, delete** (full set from PhrasesTab). Edit mode uses the same inline textarea + Save/Cancel buttons; plain Enter commits, Ctrl/Cmd+Enter newline, Escape cancels.
    - Live-refresh via `subscribe` on `{ type: 'skills' }`.
11. **`src/components/tabs/SkillsTab.css`** (new) — copy `FutureTab.css`/`PhrasesTab.css` conventions, namespaced under `.skills-*` (textarea sizing rules identical to `.future-input--filter`), plus icon sizing rules scoped under `.skills-row`.
12. **`src/components/LeftPane.tsx`** — add `{ id: 'skills', label: 'Skills', content: <SkillsTab /> }` to the tabs array. **Always enabled** (no `disabled` flag — it's global).

### Notes
- Skills is the only global data type; renaming/deleting a project does not touch `skills.json` (it lives at the root, so `restamp_project_id`'s per-project glob won't reach it — no change needed there).
- No filtering is added to the input (the request specifies "enter text → Enter adds"); keeping it focused and simple.
